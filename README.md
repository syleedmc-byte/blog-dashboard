# 블로그 통계 대시보드

디엠씨미디어 월간 블로그 통계를 자동으로 반영해 보여주는 대시보드입니다.
엑셀 파일을 코드에 손으로 옮겨 적는 과정이 없습니다 — **엑셀을 `data/` 폴더에 넣고
스크립트 한 번만 실행하면** 화면 전체(수치·차트·게시글·카테고리)가 자동으로 갱신됩니다.

---

## 매달 반복하는 작업 (이것만 하면 됩니다)

1. 새 월 시트가 추가된 엑셀 파일을 `data/` 폴더에 넣습니다 (기존 파일은 지우지 않아도 되고,
   덮어써도 됩니다 — 폴더 안에서 **가장 최근에 수정된 `.xlsx` 파일 하나**를 자동으로 찾습니다).
2. 아래 명령을 한 번 실행합니다.

   ```bash
   npm run update
   ```

   (`node scripts/update.js` 와 동일합니다.) 실행하면 새로 반영된 월과, 대조해볼 수 있는
   핵심 수치(조회수·순방문자수·유입경로 1위 등)가 터미널에 출력됩니다. 이 숫자를 엑셀 원본과
   눈으로 한 번 대조해 보세요.
3. `npm run dev` 로 로컬에서 화면을 확인합니다.
4. 문제가 없으면 커밋 후 푸시합니다. (GitHub Pages/Netlify/Vercel 중 무엇을 쓰든, 푸시하면
   자동으로 재빌드·재배포됩니다 — 아래 [배포](#배포) 참고)

   ```bash
   git add data src/data
   git commit -m "update: 2026-08 데이터 반영"
   git push
   ```

`npm run dev` / `npm run build` 를 실행할 때도 그 직전에 `update` 스크립트가 자동으로 한 번
더 실행됩니다(`predev`/`prebuild`). 그래서 엑셀만 바꿔두고 `npm run dev`만 실행해도 항상
최신 데이터로 그려집니다. 다만 매달 처음 반영할 때는 위 2번처럼 `npm run update`를 직접
실행해서 터미널에 뜨는 검증용 수치를 눈으로 확인하는 것을 권장합니다.

## 다음 달부터 이렇게 요청하면 됩니다 (AI 어시스턴트용 안내)

사람이 Claude 등 AI 어시스턴트에게 다음처럼 짧게 말하면:

> "이번 달 시트 추가했어, 갱신해줘" / "8월 데이터 반영해줘"

AI는 이 README만 보고 아래 순서를 그대로 실행하면 됩니다.

1. `data/` 폴더에 사람이 새로 넣어준 엑셀 파일이 있는지 확인한다 (없다면 먼저 요청해서 받는다).
2. 이 프로젝트 루트에서 `npm run update` 를 실행한다. **엑셀 값을 코드에 직접 타이핑하지 않는다** —
   반드시 스크립트가 읽도록 한다 (오타·누락 방지가 이 스크립트를 만든 이유이므로).
3. 터미널에 출력되는 "검증용 수치"를 실제 엑셀 파일 값과 대조해 확인한다. 특히 유입경로/유입검색어
   이름과 숫자가 한 글자도 다르지 않은지 확인한다.
4. `npm run dev`로 로컬 화면을 열어 새 월 탭이 추가됐는지, 숫자가 정상인지 확인한다.
5. 문제가 없으면 사람에게 확인받고 `git add`, `git commit`, `git push` 한다 (git push는 배포에
   영향을 주는 행동이므로 실행 전 반드시 사람에게 확인받는다).
6. 화면 디자인(색상, 레이아웃, 카드 스타일)이나 파싱 로직은 이미 확정된 상태이므로, 사람이 별도로
   요청하지 않는 한 임의로 바꾸지 않는다.

## 엑셀 파일 규칙

- 시트 이름은 `키워드 분석(N월)` / `카테고리 분류(N월)` 형식이어야 합니다 (예: `키워드 분석(8월)`,
  `카테고리 분류(8월)`). 공백이나 괄호 유무는 자동으로 허용됩니다.
- "키워드 분석(N월)" 시트 안에는 **유입경로 표("유입분석")와 유입검색어 표("유입 검색어")가
  서로 다른 열에 나란히 있습니다.** 파싱은 고정된 열 번호가 아니라 이 제목 텍스트를 먼저 찾은
  뒤 그 열을 기준으로 읽으므로, 두 표의 위치가 바뀌어도, 달마다 표 위치가 조금씩 달라져도
  올바른 표에서 올바른 값을 읽습니다 (`src/lib/parseExcel.js` 참고).
- 아직 값이 채워지지 않은 빈 월 시트(템플릿만 있는 상태)는 자동으로 건너뜁니다. 데이터가
  채워진 뒤 `npm run update`를 다시 실행하면 자동으로 새 탭이 추가됩니다.
- 인기 게시글 제목에 하이퍼링크가 걸려 있으면 원문 링크(🔗)도 함께 표시됩니다.
- "카테고리 분류" 시트에서 동점 카테고리는 임의로 자르지 않고, 같은 순위(동점)를 모두
  top5에 포함해서 표시합니다 (그래서 어떤 달은 카테고리가 5개보다 많을 수 있습니다).

## 로컬에서 실행하기

Node.js 18 이상이 필요합니다.

```bash
npm install
npm run update   # data/ 폴더의 엑셀을 읽어 src/data/dashboard-data.json 생성
npm run dev      # http://localhost:5173
```

## 프로덕션 빌드

```bash
npm run build    # prebuild 훅이 update를 먼저 실행한 뒤 dist/ 를 생성합니다
npm run preview  # 빌드 결과를 로컬에서 미리보기
```

## 배포

이 저장소를 GitHub에 올려두고, 아래 셋 중 하나로 연결하면 **`git push` 한 번으로 자동
재빌드·재배포**됩니다.

### Netlify 또는 Vercel (권장 — 설정이 가장 간단함)

1. [Netlify](https://app.netlify.com) 또는 [Vercel](https://vercel.com)에서 "Add new site /
   New Project" → 이 GitHub 저장소 선택.
2. 빌드 명령: `npm run build`, 배포 폴더(publish/output directory): `dist`.
3. 완료 후에는 `main` 브랜치에 push할 때마다 자동으로 재빌드·재배포됩니다.

### GitHub Pages

1. `vite.config.js`의 `base` 값을 저장소 이름에 맞게 바꿉니다.
   ```js
   base: '/blog-stats-dashboard/', // 저장소 주소가 github.com/USER/blog-stats-dashboard 라면
   ```
2. `npm run deploy` 실행 (`gh-pages` 패키지로 `dist/`를 `gh-pages` 브랜치에 올립니다).
3. 저장소 **Settings → Pages**에서 Source를 `gh-pages` 브랜치로 지정합니다.
4. 이 방식은 push만으로 자동 배포되지는 않으므로(수동으로 `npm run deploy` 필요), 완전
   자동화를 원하면 Netlify/Vercel을 권장합니다. (GitHub Actions로 자동화할 수도 있습니다.)

## 프로젝트 구조

```
data/                          엑셀 원본 (매달 새 파일로 교체/추가)
scripts/update.js              엑셀 → src/data/dashboard-data.json 변환 스크립트 ("npm run update")
src/
  lib/parseExcel.js            엑셀 파싱 핵심 로직 (제목 텍스트 기반 탐색, 동점 처리 등)
  data/dashboard-data.json     update.js가 생성하는 정적 데이터 (커밋되어 git 히스토리로 추적됨)
  components/                  KPI 카드, 트렌드 차트, 게시글, 유입경로/검색어, 기기별 도넛, 카테고리 버블맵
  theme.js                     차트 색상 (참고 디자인 blog_dashboard_monthly_18.html 팔레트와 동일)
  App.jsx                      전체 화면 조립
```

## 디자인 기준

색상·카드 스타일·레이아웃은 `blog_dashboard_monthly_18.html` (및 그 배포본인
https://dmc-blog-dashboard-test.netlify.app/ )을 기준으로 맞췄습니다. 다만 이 프로젝트는
**엑셀 기반 자동 반영 + 정적 배포**를 위한 것이라, 참고 디자인에 있던 화면에서 직접
드래그/더블클릭으로 수정하고 Firebase에 저장하는 기능은 포함하지 않습니다(다음 달부터는
엑셀만 바꾸면 되므로 그 기능이 필요 없습니다). 카테고리 영역은 데스크탑에서는 브랜드
중심의 원형 마인드맵으로, 모바일 화면(700px 이하)에서는 읽기 쉬운 목록형으로 자동 전환됩니다.
